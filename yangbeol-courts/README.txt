양벌 테니스 돔 예약 현황 — 개인용

1. 로컬 실행 (Windows)
   Node.js 24 이상이 필요합니다. 추가 라이브러리 설치나 npm install은 필요 없습니다.
   start.bat를 더블클릭한 다음 브라우저에서 http://localhost:8787 에 접속하세요.
   또는 이 폴더에서 터미널을 열고 npm start 를 실행하세요.
   종료는 서버 창에서 Ctrl+C 입니다. 서버 실행 중에만 조회할 수 있습니다.
   index.html 파일을 직접 더블클릭해서 열지 마세요.

2. 사용법
   날짜를 고르면 12개 코트를 조회합니다. 이전/다음 날짜, 오늘 버튼도 지원합니다.
   예약 가능만 표시하거나 오전/오후/야간으로 필터링할 수 있습니다.
   모바일은 C안 시간표로 1~4번 / 5~8번 / 9~12번 코트를 전환합니다.
   주간 날짜 버튼으로 날짜를 고를 수 있고, 상단 날짜 선택 영역은 스크롤 시 고정됩니다.
   코트 묶음 전환은 추가 서버 요청 없이 즉시 반영됩니다.
   요약 수치는 전체 12개 코트 기준입니다. PC에서는 전체 코트를 표시합니다.
   화면 너비 380px 이하에서는 오늘 버튼 대신 날짜 선택/주간 날짜 버튼을 사용하세요.
   예약 가능한 칸 또는 코트 이름을 누르면 공식 사이트의 해당 날짜/코트가 열립니다.
   이 프로그램은 현황만 조회합니다. 실제 신청은 공식 사이트에서 진행하세요.
   휴관일, 예약불가, 마감, 예약완료, 추첨접수, 조회 실패를 구분합니다.
   조회 실패를 빈자리로 표시하지 않습니다. 날짜 상태가 확인돼야 예약가능으로 표시합니다.
   요금은 API의 기준금액이며 최종 요금 및 할인은 공식 사이트에서 확인하세요.
   예약자/단체명은 중계 응답과 화면에 포함하지 않습니다.
   한국 시간 기준 오늘 날짜 및 조회 시각을 사용합니다.

3. 조회와 캐시
   로그인이나 비밀번호 없이 공개 조회 요청만 사용합니다.
   코트별 날짜 상태와 시간대 상태를 함께 조회합니다 (한 날짜당 최대 24개 요청).
   코트 3개씩 조회하며 동일 날짜 중복 요청은 합칩니다.
   정상 조회 결과는 메모리에 15초간 보관합니다. 새로고침도 이 시간에는 같은 결과입니다.
   자동 반복 조회는 하지 않습니다. 정보는 조회 시점 기준입니다.
   일부 코트 조회가 실패하면 나머지 결과와 실패 표시를 함께 보여 줍니다.
   공식 사이트의 내부 API 또는 상태 코드가 변경되면 수정이 필요합니다.

4. Git 정적 호스팅 배포
   화면은 CSS/JavaScript를 포함한 단일 index.html입니다. 빌드 과정이 없습니다.
   하지만 GitHub Pages 등에 index.html만 올리면 실시간 조회는 작동하지 않습니다.
   CORS 때문에 HTTPS 중계 서버 또는 서버 함수가 별도로 필요합니다.
   중계를 배포한 뒤 index.html의 API_BASE를 중계 서버의 HTTPS origin으로 바꾸세요.
   중계는 GET /api/reservations?date=YYYY-MM-DD 계약을 유지해야 합니다.
   서버 함수 구현 시 lib/reservations.mjs를 재사용할 수 있습니다 (표준 fetch 사용).
   현재 server.mjs는 개인 PC용으로 127.0.0.1에만 바인딩합니다.
   원격 배포 시 호스팅 환경에 맞는 바인딩/HTTPS/접근제어/요청 제한을 설정하세요.
   ALLOWED_ORIGIN 환경변수로 특정 프런트엔드 origin의 CORS 읽기를 허용할 수 있습니다.
   예: https://example.github.io (저장소 경로 제외). 이것은 인증/접근제어 기능은 아닙니다.
   현재 파일은 로컬 테스트용이며 인터넷 배포는 수행하지 않았습니다.

5. 문제 해결
   포트 충돌: 기존 서버 종료 또는 PowerShell에서 $env:PORT='8788'; npm start
   이 경우 http://localhost:8788 에 접속하세요.
   인증서 오류: 실행 명령의 --use-system-ca가 있는지 확인하세요.
   사내망의 경우 회사 인증서가 Windows에서 신뢰되는지 확인하세요.
   인증서 검증은 끄지 않습니다.
   데이터 조회 오류: 잠시 후 다시 조회하고 공식 사이트도 정상 접속되는지 확인하세요.

6. 검증
   npm test (Node.js 기본 테스트 러너, 외부 의존성 없음)
   날짜 검증, 접수 불가일의 빈 시간 오표시 방지, 휴관, 미확인 상태,
   일부/전체 실패, 요청 병합, 캐시 만료, 예약자 정보 제외를 검증합니다.

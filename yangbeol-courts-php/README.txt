양벌 테니스 돔 예약 현황 — 닷홈 PHP 버전

필수 환경
- PHP 7.4 이상 + cURL 확장(curl_multi 포함). 닷홈에서는 PHP 8.2 또는 8.4 권장.
- HTTPS 외부 접속 및 임시 폴더 쓰기 가능.
- Node.js, npm, Composer, DB, 추가 PHP 라이브러리는 필요하지 않습니다.

업로드
1. 닷홈의 PHP 웹호스팅을 준비합니다. 닷홈빌더 전용 상품이 아닌 웹호스팅을 사용합니다.
2. 마이닷홈에서 FTP 접속 정보를 확인하고, 웹 문서 루트(일반적으로 html)에 접속합니다.
3. 아래 구조를 그대로 올립니다. 기존 홈페이지가 있으면 tennis 같은 하위 폴더에 올려도 됩니다.

   html/                        또는 html/tennis/
     index.html
     api/
       reservations.php
     lib/
       reservations.php

4. https://계정아이디.dothome.co.kr/ 또는 /tennis/ 에 접속합니다.
5. 날짜를 골라 12개 코트가 조회되는지 확인합니다.

현재 화면은 모바일 C안(4개 코트 묶음)과 PC용 12개 코트 전체 시간표를 지원합니다.
주간 날짜 선택, 시간대 필터, 예약 가능만, 공식 예약 페이지 링크를 포함합니다.
API 주소는 화면 파일 기준 api/reservations.php 입니다. 폴더명이 바뀌어도 별도 설정이 없습니다.
HTML 파일을 직접 더블클릭해 열면 조회할 수 없습니다. 반드시 PHP 웹호스팅 주소로 접속하세요.

조회 확인
브라우저에서 api/reservations.php?date=2026-11-05 를 열면 JSON 응답을 볼 수 있습니다.
예약자/단체명은 응답에 포함하지 않습니다. 실제 예약은 공식 사이트에서 진행합니다.
날짜 접수 상태와 시간대 상태를 함께 확인합니다. 실패/미확인 칸을 예약가능으로 표시하지 않습니다.
정상 결과는 15초 캐시합니다. 캐시는 서버 임시 폴더에 생성하며, 불가하면 lib/cache를 사용합니다.
같은 설치에서 한 번에 하나의 날짜를 조회합니다. 동시 요청 시 잠시 후 다시 시도 안내가 나옵니다.
부분 실패는 정상 결과와 함께 표시하고, 전체 실패는 HTTP 502와 오류 메시지를 반환합니다.
요청은 코트 3개(6개 HTTPS 요청)씩 처리하고 전체 20초 예산을 적용합니다.
첫 3개 코트가 모두 실패하면 추가 요청 없이 오류를 반환합니다.
자동 반복 조회는 없습니다. 접속 성공 및 사용량 제한은 실제 닷홈 계정에서 확인해야 합니다.

오류 코드
CURL_28: 예약 사이트 연결/응답 시간 초과
CURL_6: 서버 주소(DNS)를 찾지 못함
CURL_7: 예약 사이트에 연결할 수 없음
CURL_60 등: TLS 인증서 확인 실패 — 호스팅 인증서 환경을 점검. 검증을 끄지 않습니다.
HTTP 403/429: 원본 사이트 접근 제한/요청량 제한 가능. 오류 본문과 호스팅 로그 확인.
PHP cURL 확장 필요: 호스팅 업체에 cURL/curl_multi 사용 가능 여부 확인.
캐시 폴더 오류: 임시 폴더 또는 lib/cache의 소유자 쓰기 권한을 확인하세요. 777 설정은 불필요합니다.
API 페이지에서 PHP 코드가 그대로 보이면 PHP가 실행되지 않는 호스팅/경로입니다.

로컬 개발 확인(선택)
PHP가 설치된 PC에서 이 폴더를 연 다음:
  php -S 127.0.0.1:8789
브라우저에서 http://127.0.0.1:8789/ 에 접속합니다.
Windows PHP에서는 php.ini에 cURL 확장과 신뢰하는 CA 인증서 설정이 필요할 수 있습니다.
로컬 Node.js 버전은 별도 yangbeol-courts 폴더로 유지합니다.

파일 중 tests와 README는 호스팅에 올리지 않아도 됩니다.
